## 已修复

- 导航使用可撤销的计时任务和版本标识，连续选择以最后一次为准；前进、后退、手动修改锚点与离开页面取消旧任务。同一摄影锚点内的不同分类也写入独立历史状态。
- 首页分类、视频封面、设备图片继续使用原生 `picture`、响应式资源及原有懒加载范围。每次请求与解码共用 12 秒期限，自动重试一次，随后显示原位重试按钮；旧任务不能回写当前状态。
- 超时后的重试使用独立恢复地址，避免浏览器复用仍挂起的请求；正常首次请求不增加参数，保留原缓存路径。包括手动重试在内，每次尝试均有独立地址。
- 触屏或手写笔打开作品目录时聚焦关闭按钮；鼠标、键盘打开仍聚焦搜索，关闭恢复原入口。移动搜索字号为 16px，避免支持此行为的浏览器因小字号自动放大。

- 动态影像标题和过场不再固定显示 `00:06`，首页木星短片的真实时长保持。移除网站地图中的固定更新时间；校正真机验收文档对匿名设备分类、浏览记录及原始 IP 的说明。

## 复查额外发现并修复

1. **窄横屏竖图可能越过图片区域顶部。** 720×450 下，自动网格行被说明区压缩，竖图顶部实测为 -43px。移动布局现按内容高度排列两行，由弹窗负责纵向滚动；保留图片适配比例和现有排版。已补充窄横屏、窄竖屏及横图/竖图的边界断言。
2. **设备轮播会吞掉图片重试按钮的鼠标点击。** 轮播的 `pointerdown` 原先无条件捕获指针；现跳过按钮，重试不再启动拖动。浏览器测试实际点击后恢复成功，原拖动与横向轮播回归通过。
3. **弹窗快速关闭再打开时，旧关闭事件可能清空新内容。** Linux 发布检查暴露目录聚焦/清空和视频关闭清理时序问题。目录、大图、视频均忽略已重新打开时才到达的旧 `close` 事件；视频按钮、Esc、背景点击在关闭时同步停止播放器。补充同一轮 JavaScript 中连续关开目录、大图和视频的回归，防止仅靠增加等待掩盖问题。

本轮没有发现需要整体重设计才能解决的问题，未调整首页五栏展开、无限画布、留言位置或内容结构。

## 两个大视频：仍未修复

以实际文件总长度分别请求开头、中间、最后 1024 字节：

| 视频 ID | 文件字节数 | 开头 / 中间 / 末尾响应 | Content-Range | 取回的数据 |
| --- | ---: | --- | --- | --- |
| star-dream | 432757530 | 200 / 200 / 200 | 均缺失 | 三次都是文件开头，相同 SHA-256 |
| tianjian-promo | 188148377 | 200 / 200 / 200 | 均缺失 | 三次都是文件开头，相同 SHA-256 |

两者返回 `Server: tcbgw` 和 `Accept-Ranges: bytes`，但没有真实分段响应。检查只读取少量数据并关闭连接，没有下载整个文件。`python tools/verify-video-ranges.py` 可重复检查，会在缺少正确 206、范围、长度或数据量时返回非零状态，未将它伪装为已通过的静态检查。

真实 Chromium/Edge 媒体请求发出了 `Range: bytes=0-`，两个文件仍收到 200。关闭弹窗后确认 `src` 被清除、`paused=true`、`readyState=0`，观察期内没有新增视频请求。**正常播放、拖动进度仍未通过验收。**

授权后进一步核对了现有静态托管、HTTP 路由及 CloudBase 专用 CDN 配置接口：

- 默认域名的 CDN 源站为 `prod.tcloudbaseapp-in.tencentcloudbase.com`，`RangeOriginPull.Switch=off`，普通缓存为 120 秒。通用 CDN 全账户查询权限不开放，但 CloudBase 对应域名的专用查询正常，不能把通用接口拒绝误判为完全无法读取配置。
- 使用既有 CLI 身份，在内存中签名读取现有私有 COS 存储桶。两个文件的开头、中间、末尾均实际返回 **206、正确 Content-Range 和 1024 字节正文**，不同位置摘要不同。未公开存储桶，未输出签名、密钥或令牌。
- 绕过 CDN、以原域名的 Host/SNI 直接请求配置中的网关源站，仍返回 **200、432757530 字节声明、无 Content-Range**；响应表明网关向 Tencent-COS 的上游请求也返回了 200。示例请求 ID：`28273e6b-1d54-45d4-a590-650928a5b381`。
- 据此将问题定位到 **CloudBase 默认静态网关的 Range 回源处理**。CDN 开关关闭也需关注，但它的直接上游尚不满足分段前提；未盲目启用，以免引入回源失败。没有改写响应头冒充支持，没有调整其他网关路由、存储权限、计费或托管服务。

剩余步骤：向 CloudBase 平台提供上述请求 ID、默认域名及 `Range: bytes=1048576-1049599`，确认/修复默认静态网关向 COS 转发 Range 的能力；源站真实支持 206 后，再按两个视频路径配置分片回源并重跑三处范围、浏览器播放与拖动测试。本轮未擅自发送工单或消息。参考：[CloudBase 资源管理](https://docs.cloudbase.net/hosting/manage)、[静态托管 SDK](https://docs.cloudbase.net/api-reference/manager/node/hosting)、[腾讯云分片回源前提](https://intl.cloud.tencent.com/zh/document/product/228/7184)。
