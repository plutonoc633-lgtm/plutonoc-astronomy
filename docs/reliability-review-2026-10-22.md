## 两个大视频：修复前的故障证据

以实际文件总长度分别请求开头、中间、最后 1024 字节：

| 视频 ID | 文件字节数 | 开头 / 中间 / 末尾响应 | Content-Range | 取回的数据 |
| --- | ---: | --- | --- | --- |
| star-dream | 432757530 | 200 / 200 / 200 | 均缺失 | 三次都是文件开头，相同 SHA-256 |
| tianjian-promo | 188148377 | 200 / 200 / 200 | 均缺失 | 三次都是文件开头，相同 SHA-256 |

两者返回 `Server: tcbgw` 和 `Accept-Ranges: bytes`，但没有真实分段响应。检查只读取少量数据并关闭连接，没有下载整个文件。`python tools/verify-video-ranges.py` 可重复检查，会在缺少正确 206、范围、长度或数据量时返回非零状态，未将它伪装为已通过的静态检查。

真实 Chromium/Edge 媒体请求发出了 `Range: bytes=0-`，两个文件仍收到 200。关闭弹窗后确认 `src` 被清除、`paused=true`、`readyState=0`，观察期内没有新增视频请求。**正常播放、拖动进度仍未通过验收。**

授权后进一步核对了现有静态托管、HTTP 路由及 CloudBase 专用 CDN 配置接口：

- 默认域名的 CDN 源站为 `prod.tcloudbaseapp-in.tencentcloudbase.com`，`RangeOriginPull.Switch=off`，普通缓存为 120 秒。通用 CDN 全账户查询权限不开放，但 CloudBase 对应域名的专用查询正常，不能把通用接口拒绝误判为完全无法读取配置。
- 使用既有 CLI 身份，在内存中签名读取现有私有 COS 存储桶。两个文件的开头、中间、末尾均实际返回 **206、正确 Content-Range 和 1024 字节正文**，不同位置摘要不同。未公开存储桶，未输出签名、密钥或令牌。
- 绕过 CDN、以原域名的 Host/SNI 直接请求配置中的网关源站，仍返回 **200、432757530 字节声明、无 Content-Range**；响应表明网关向 Tencent-COS 的上游请求也返回了 200。示例请求 ID：`28273e6b-1d54-45d4-a590-650928a5b381`。
- 据此将问题定位到 **CloudBase 默认静态网关的 Range 回源处理**。CDN 开关关闭也需关注，但它的直接上游尚不满足分段前提；未盲目启用，以免引入回源失败。没有改写响应头冒充支持，没有调整其他网关路由、存储权限、计费或托管服务。

此前将后续处理止步于平台工单并不充分。继续验证后，已在同一 CloudBase 环境内完成可用的播放修复，见下一节。默认静态网关本身仍不正确转发 Range，未声称修改了平台实现。参考：[CloudBase 资源管理](https://docs.cloudbase.net/hosting/manage)、[静态托管 SDK](https://docs.cloudbase.net/api-reference/manager/node/hosting)、[腾讯云分片回源前提](https://intl.cloud.tencent.com/zh/document/product/228/7184)。

## 大视频播放修复与验证

- 新增独立事件函数 `plutonoc-media`，HTTP 路径 `/media?id=star-dream`、`/media?id=tianjian-promo`。仅这两个固定作品可获取一小时有效的 COS 读取地址；播放器通过 302 直接读取原来的私有存储对象，视频数据不经过云函数。原文件、存储桶访问权限、现有内容发布、统计、留言及其他路由均保持。
- 服务端只接受 GET / HEAD，不接受客户端提供的路径、域名或存储桶。签名取当前调用的 `context.environment`，不缓存冷启动环境变量中的凭证；授权缺失或签名异常返回 503，不输出密钥或签名地址。
- 兼容检查发现后台读取视频信息时设置了不必要的 `crossOrigin=anonymous`，会使跨域重定向后的原生视频元数据读取被浏览器拦截。现读取时长、宽高不再要求画布跨域权限；使用真实 MP4 和无 CORS 响应的模拟来源完成浏览器回归，无登录或发布请求。后台已部署为 `plutonoc-studio-014`，构建 `2609157378`，时间 `2026-10-22T11:25:46.515Z`，脚本资源版本 `20261022-media-1`。
- 两个新入口各自完成开头、中间、末尾 1024 字节验证，六次均为真实 **206**、正确总大小与 Content-Range、1024 字节正文，且对应原始 COS 分段摘要一致。
- 本机 Edge 浏览器使用真实云端视频，在 4 MiB/s、30ms 模拟链路下，实际解码 3840×2160 / 1920×1080 画面，成功播放；跳到 50% 和 92% 进度均产生对应的新分段请求并继续播放。首次画面就绪分别约 3.1 秒和 0.65 秒，四次跳转恢复约 0.9–1.2 秒。该采样不代表所有访问者或手机表现。
- 关闭后清除播放器源、暂停并停止请求；未打开视频前没有请求正式影片。`tools/verify-video-playback.cjs` 为显式运行的真实媒体验证，关闭统计与留言，普通 CI 布局回归模拟播放入口，避免访问正式数据。
- `tools/test-media.cjs` 覆盖白名单、伪造路径与字段、非法方法、HEAD、跨调用凭证更新和异常失败隔离。当前共 58 项 Node 自动化检查通过，内容生成、关键样式和静态检查通过。

云函数与新 HTTP 入口已部署并验证。官网地址下复测结果：星辰行梦首画面约 3.48 秒，宣传片约 0.42 秒；程序跳转至中段/末段后均继续播放。另通过浏览器鼠标操作实际拖动原生进度条到约 50% 和 92%，四次恢复约 0.46–0.86 秒，均无媒体错误。关闭两个视频后新增请求与未完成请求都为零。条件仍为本机 Edge、4 MiB/s、30ms 模拟链路；不等同于真实手机或所有用户网络验收。
